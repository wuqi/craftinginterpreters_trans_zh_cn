# 第 11 章 draft 反思建议清单

> 只诊断，不动手。逐条对照原文。修订时按此清单改。

## (i) 准确性 —— 增译 / 误译 / 漏字

1. **L272 漏字**：原文 "We'll know not just that an expression *is* a variable, but
   *which* variable it is." 译文「我们不知道某个表达式**是**个变量，还知道它是**哪个**
   变量。」漏了「只」。「not just ... but ...」= 「不**只**……还……」。
   → 改「我们**不只知道**某个表达式**是**个变量，还知道它是**哪个**变量。」

2. **L21-22 增译**：原文 "you can figure out which declaration a variable name refers
   to just by reading the text" 没有「你不用做别的」。删掉，留「光读一读程序的文本，就能
   弄清……」。

3. **L100 误字**：「包围作用域里可能不止一个**好**变量用了同一个名字」——「好」是衍字，
   语义不通。→ 「包围作用域里可能不止一个变量用了同一个名字」。

4. **L49 指代**：定义句「出现于**它**之前」中「它」指代不明（指用法？表达式？）。
   → 「出现于**该用法**之前」。

5. **L130 强调范围**：原文 `<span name="tricky">Before</span> you type this in and run
   it` 只强调 `Before`。译文把 span 拉长包住「在你把它敲进去、运行之前」整句，强调过宽。
   → 收缩为「在你把它敲进去、运行<span name="tricky">之前</span>，先想清楚……」

6. **L270 首现重复**：`semantic analysis` 已在 L15 首现标注。此处第二次出现不该再标英文。
   → 「就是**语义分析**的一个例子」，删「（semantic analysis）」。

## (ii) 流畅度 —— 中文语法 / 冗余 / 机翻痕迹

7. **L213 双「在」拗口**：「在我标的第一行处，在作用域里的只有 `a`。」
   → 「在标了 1 的那一行处，作用域里只有 `a`。」

8. **L363 直译生硬**：原文 "they turn around and apply the Visitor pattern"，
   「转过身来」是字面直译。→ 「它们都反过来，对给定的语法树节点套用访问者模式」。

9. **L326 用词重复**：L158 已用「动态化身」，L326 又「化身在一个类里」。
   → 「体现在一个类里」。

10. **L341 略生硬**：「好深入它们的子树」→「好钻进它们的子树里」。

11. **L600 歧义**：「增量地重新语法解析、重新解析用户程序的一部分」——两个「解析」易混。
    → 「增量地重新做语法解析、重新做作用域解析」。

## (iv) 术语 —— 与术语表一致 / 结构约束

14. **resolve 的动词形态**：术语表定 `resolve → 作用域解析`、`resolver → 作用域解析器`。
    本稿动词多用「解析」（如「解析一个变量」「解析块」），名词一律「作用域解析器」。
    **决策**：`parser → 语法解析器`、`parsing → 语法解析` 固定带「语法」前缀；凡出现
    resolve 之处一律简作「解析」，靠「语法」前缀与 parse 区隔，不写成笨重的「作用域解析
    块」。此为有意的简省，非漂移，回头在 glossary 加注说明。
15. 其余术语核对通过：binding→绑定、semantic/syntactic analysis→语义分析/语法分析、
    persistent data structure→持久化数据结构、hoisting→提升、side table→侧表、
    shadowing→遮蔽、initializer→初始化器。均首现标英文。
