类与实例

对物件太过执着会毁掉你。只有——当你足够珍视一件事物时，它才会拥有自己的生命，不是吗？ 而事物——美丽的事物——存在的全部意义，不就是把你和某种更大的美联系起来吗？

唐娜·塔特（Donna Tartt），《金翅雀》

clox 里最后一块尚未实现的地盘就是面向对象编程。面向对象编程是一 捆彼此缠绕的特性：类、实例、字段、方法、初始化器和继承。用相对高层的 Java，我们把这些 塞进了两章里。现在我们要用 C 编码——那感觉就像用牙签搭埃菲尔铁塔的模型——于是我们打算 用三章走完同一片地形。这让实现过程变成一次悠闲的散步。在闭包和垃圾回收这样 辛苦的章节之后，你该歇口气了。事实上，从这里往后本书应该都会很轻松。

对面向对象编程有强烈看法的人——也就是「所有人」——往往以为 OOP 就是某一串非常具体的 语言特性，但实际上那是一整片有待探索的空间，每门语言都有自己的配料和配方。

Self 有对象但没有类。CLOS 有方法但不把它们挂在特定的类上。C++ 最初没有运行时多态—— 没有虚方法。Python 有多重继承，Java 没有。Ruby 把方法挂在类上，但你也可以在单个对象上 定义方法。

本章我们覆盖前三个特性：类、实例和字段。这是面向对象中有状态的那一面。接下来两章，我们会 把行为和代码复用挂到这些对象上。

紧跟在 class 关键字后面的是类名。我们取那个标识符，把它作为字符串加进外围函数的常量表。 正如你刚看到的，打印一个类会显示它的名字，所以编译器需要把这个名字字符串塞到运行时能 找到的地方。常量表就是干这个的办法。

类的名字还用来把类对象绑定到一个同名的变量上。所以我们在 吃掉它的词法单元之后立刻声明一个同名变量。

我们本可以把类声明做成表达式而不是语句——说到底它本质上就是个产生值的字面量。 那样用户就得自己显式地把类绑定到变量上，比如：

有点像 lambda 函数，只不过对象是类。但既然我们总体上希望类是有名字的，把它们当作声明 来处理也说得通。

我们从常量表里加载类名的字符串，传给 newClass()。它创建一个给定名字的新类对象。我们把 它压栈，搞定。如果这个类被绑定在一个全局变量上，那么编译器对 defineVariable() 的调用 会发射代码，把那个对象从栈里存进全局变量表。否则它正好就落在我们需要的位置：一个新 局部变量。

「局部」类——声明在函数体或块体内部的类——是个不寻常的概念。很多语言根本不允许。 但既然 Lox 是一门动态类型的脚本语言，它对程序的顶层和函数、块的函数体一视同仁。类不过是 另一种声明，既然你能在块里声明变量和函数，也就能在里面声明类。

就是这样，我们的 VM 现在支持类了。你可以跑这个：

class Brioche {}
print Brioche;

不幸的是，你能对类做的事只有打印，所以接下来是让它们更有用。

27 . 3类的实例

类在一门语言里有两个主要用途：

  • 它们是你创建新实例的方式。 有时这需要一个 new 关键字，有时是对类对象的一次方法 调用，但不管怎样你通常都要设法按名字提到那个类，才能拿到一个新实例。

  • 它们容纳方法。 方法定义了这类对象的所有实例如何表现。

方法要等到下一章，所以现在我们只操心第一部分。类要能创建实例，我们首先需要实例的表示。

} ObjClass;
object.h
加在结构体 ObjClass 之后

typedef struct {
  Obj obj;
  ObjClass* klass;
  Table fields; 
} ObjInstance;


ObjClass* newClass(ObjString* name);
object.h, 加在结构体 ObjClass 之后

实例知道自己的类——每个实例都有一个指针，指向它所属的那个类。本章我们不太用得上它， 但加上方法之后它会变得至关重要。

对这一章来说更重要的是实例怎么存自己的状态。Lox 允许用户在运行时自由地往实例上加 字段。这意味着我们需要一种可以增长的存储机制。我们可以用动态数组，但我们还想 尽快按名字查找字段。有一种数据结构正好完美契合「快速按名字访问一组值」——而且更方便的是， 我们已经把它实现过了。每个实例用一张哈希表存自己的字段。

能在运行时自由地给对象加字段，这是大多数动态语言与静态语言之间一个很大的实际差异。 静态类型语言通常要求字段显式声明。这样编译器确切知道每个实例有哪些字段，可以据此确定 每个实例需要多少内存，以及每个字段在这块内存中的偏移量。

在 Lox 和其他动态语言里，访问一个字段通常是一次哈希表查找。是常数时间，但开销仍然不小。在 C++ 这样的语言里，访问字段跟用一个整数常量去偏移指针一样快。

27 . 4Get 与 Set 表达式

我们针对实例的对象表示已经能存状态了，所以剩下的就是把这份功能暴露给用户。字段用 get 表达式和 set 表达式来访问和修改。Lox 也不甘落后，采用了经典的「点号」语法：

eclair.filling = "pastry creme";
print eclair.filling;

那个句点——献给我的英语朋友们，它叫 full stop——作用有点像一个中缀运算符。左边有一个 先求值、产生一个实例的表达式。之后是 .，再跟一个字段名。既然有一个前置操作数，我们把 它作为中缀表达式挂进解析表。

我说「有点像」，是因为 . 右边不是表达式，而是一个单独的标识符，它的语义由 get 或 set 表达式本身处理。它其实更接近后缀表达式。

  [TOKEN_COMMA]         = {NULL,     NULL,   PREC_NONE},
compiler.c
替换 1 行
  [TOKEN_DOT]           = {NULL,     dot,    PREC_CALL},

  [TOKEN_MINUS]         = {unary,    binary, PREC_TERM},
compiler.c, 替换 1 行

和其他语言一样，. 运算符绑定得很紧，优先级和函数调用里的圆括号一样高。解析器吃掉点号 词法单元之后，会分派到一个新的解析函数。

compiler.c
加在 call() 之后
static void dot(bool canAssign) {
  consume(TOKEN_IDENTIFIER, "Expect property name after '.'.");
  uint8_t name = identifierConstant(&parser.previous);

  if (canAssign && match(TOKEN_EQUAL)) {
    expression();
    emitBytes(OP_SET_PROPERTY, name);
  } else {
    emitBytes(OP_GET_PROPERTY, name);
  }
}
compiler.c, 加在 call() 之后

解析器预期在点号后面紧接着找到一个属性名。我们把那个词法单元的词素 作为字符串加载进常量表，好让名字在运行时可用。

编译器这里用「属性」而不是「字段」，别忘了，Lox 还允许你用点号语法访问一个方法而不调用 它。「属性」是我们用来指代实例上任何可访问的具名实体的总称。字段是由实例状态支撑的那 一部分属性。

我们有两条新的表达式形式——getter 和 setter——都由这一个函数处理。如果我们在字段名后面 看到一个等号，那必然是一条给字段赋值的 set 表达式。但我们并不总是允许编译字段后面 的等号。考虑：

a + b.c = 3

按 Lox 的文法，这在语法上是非法的，也就是说我们的 Lox 实现有责任检测并报告这个错误。 如果 dot() 默默地把 = 3 那部分也解析了，我们就会错误地把这段代码理解成用户写了：

a + (b.c = 3)

问题在于，set 表达式里 = 那侧的优先级比 . 那部分低得多。解析器可能在优先级太高、 不允许出现 setter 的语境里调用 dot()。为了避免错误地放行这种情况，我们只在 canAssign 为真时才解析并编译等号那部分。如果 canAssign 为假时出现了等号词法单元， dot() 会原样留下它然后返回。那种情况下，编译器最终会退回到 parsePrecedence()， 它停在这个意料之外的 = 上（它仍是下一个词法单元）并报告错误。

如果我们在确实允许等号的语境里找到了一个 =，我们就编译它后面那个表达式。之后我们 发射一条新的 OP_SET_PROPERTY 指令。它带一个操作数，表示属性名 在常量表里的索引。如果我们没有编译出 set 表达式，就假定它是 getter，发射一条 OP_GET_PROPERTY 指令，它同样带一个属性名的操作数。

你不能设置一个非字段的属性，所以我想那条指令本来也可以叫 OP_SET_FIELD，但我觉得 跟 get 指令保持一致看起来更顺眼。

习题

  1. 访问对象上不存在的字段会立刻中止整个 VM。用户没法从这个运行时错误里恢复，也没有 任何办法在尝试访问之前知道字段是否存在。用户只能自己保证只读有效字段。

    其他动态类型语言怎么处理缺失的字段？你觉得 Lox 应该怎么做？实现你的方案。

  2. 字段在运行时按字符串名字访问。但那个名字必须始终以标识符词法单元的形式直接出现在 源代码里。用户程序不能命令式地构造一个字符串值、再把它当作字段名。你觉得他们应该 能做到吗？设计一个支持这件事的语言特性并实现它。

  3. 反过来，Lox 没有任何办法从实例上移除字段。你可以把字段的值设成 nil，但哈希表里 的条目还在那儿。其他语言怎么处理这个问题？为 Lox 选择并实现一种策略。

  4. 因为字段在运行时按名字访问，操作实例状态很慢。技术上这是常数时间操作——多亏了哈希表 ——但常数因子相当大。这是动态语言比静态类型语言慢的一个主要原因。

    动态类型语言的精巧实现是怎么应对并优化这一点的？
